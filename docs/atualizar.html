Manual de atualização

Como atualizar o JARVIS na mão

Sempre que sair uma versão nova, siga este roteiro. Leva uns 3 minutos e você não perde chave, memória nem agenda.

Sem IA, sem mistério Mantém suas chaves Mantém a memória Windows
0

O que nunca é apagado numa atualização

Estes arquivos são seus e não existem no GitHub. A atualização nunca mexe neles:

ArquivoO que guarda
config/api_keys.jsonChave Gemini, chaves dos plugins (Groq, Trello, Gmail…), suas preferências
config/certs/Certificado do painel remoto
memory/long_term.jsonO que o JARVIS lembra sobre você
memory/organizer.jsonTarefas e agenda
memory/usage.json, briefing_state.jsonUso e estado do briefing
Antes de qualquer atualização, faça uma cópia da pasta config e da pasta memory para um lugar seguro. Se algo der errado, é só colar de volta.

Caminho A · você instalou com Git (recomendado)

1

Feche o JARVIS

Feche a janela do assistente. Se abriu pelo atalho sem terminal, use o ícone na bandeja ou o Gerenciador de Tarefas (processo pythonw.exe).

2

Abra o Prompt de Comando na pasta do JARVIS

Abra a pasta do projeto no Explorador, clique na barra de endereço, digite cmd e aperte Enter. Ou:

cd %USERPROFILE%\Documents\jarvis-opensource
3

Puxe a versão nova

git pull

Vai listar os arquivos que mudaram e terminar com algo como Fast-forward. Se aparecer Already up to date., você já está na última versão.

Deu erro "Your local changes would be overwritten"? Você editou algum arquivo do código. Para descartar suas edições e aceitar a versão nova, rode git checkout -- . e depois git pull de novo. Suas chaves e memória não entram nisso.
4

Reinstale as dependências se o aviso pedir

Se na lista do git pull apareceu requirements.txt ou setup.py, rode:

py setup.py

Se não apareceu, pode pular. Na dúvida, rodar não faz mal, só demora um pouco.

5

Abra e confira

py main.py

O JARVIS deve abrir normal, com suas chaves e memória no lugar. Se o atalho da área de trabalho parou de funcionar, rode criar-atalho-jarvis.bat de novo.

Caminho B · você baixou o ZIP, sem Git

1

Baixe o ZIP novo

Acesse github.com/jgm-source/jarvis-opensource, clique no botão verde Code → Download ZIP e extraia em uma pasta nova, por exemplo jarvis-novo.

2

Copie o que é seu para a pasta nova

Da pasta antiga para a nova, copie por cima:

  • config\api_keys.json
  • config\certs\ (se existir)
  • a pasta memory\ inteira
Não copie o resto. Arquivos .py, core\, plugins\, ui.py e main.py da pasta antiga são justamente o que está sendo atualizado.
3

Instale as dependências e abra

cd jarvis-novo
py setup.py
py main.py

Funcionou? Apague a pasta antiga e renomeie a nova. Rode criar-atalho-jarvis.bat para o atalho apontar para a pasta certa.

Depois de atualizar

✓

Perguntas comuns

  • Como sei qual versão eu tenho? Na pasta do JARVIS, git log -1 --format=%cd mostra a data da última atualização instalada. Compare com a data do último commit no GitHub.
  • A intro de abertura e o recado não apareceram de novo. É normal, eles tocam uma vez por PC. Para ver de novo, abra config/api_keys.json e mude "intro_shown": true para false.
  • Apareceu um campo novo nas configurações. Versões novas podem trazer plugins com chave própria. Preencha em ⚙ → PLUGIN SETTINGS. O que já estava preenchido continua igual.
  • Deu ModuleNotFoundError ao abrir. Faltou uma dependência nova. Rode py setup.py, ou instale o módulo citado com py -m pip install NOME.
  • Quero voltar para a versão anterior. Com Git: git log --oneline mostra as versões; git checkout CODIGO volta para uma delas; git checkout main retorna para a mais nova.
  • Perdi minhas chaves. Cole de volta a cópia de config e memory que você fez no passo 0. Se não fez, gere uma chave Gemini nova no AI Studio e reconfigure os plugins.
